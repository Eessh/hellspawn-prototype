# One executor seat per session; viewers unlimited; daemon mode opts out of auto-stop

Opening a project lists its running simulation workers; a user joins one as Viewer or Executor, or creates a new simulation and becomes its Executor. A session has exactly one executor seat: the executor sends user commands, starts/stops scenarios, and can hand the seat to any joined user. Executor presence is tracked by connection heartbeat — the seat counts as occupied until a configured presence timeout of silence passes, so a network blip never vacates it. Takeover requests need approval only from a present executor; a seat declared empty is taken instantly by the first requester, viewers included. Command conflicts between users are deleted by design, not resolved. Every user command carries the account that issued it, and every seat change (take, handover, presence timeout) is logged — so commands reaching real systems in live modes stay attributable.

Whenever the seat is empty, a configured grace timer runs; on expiry the worker finishes its current event, writes a checkpoint, marks the run interrupted, and exits gracefully — never a hard kill, so the run stays resumable. Daemon mode (enabled by the executor) disables the timer so the worker runs unattended (e.g. overnight Live soak tests); only project developers may take a daemon worker's seat and stop it, since developers are the ones who start background test runs. Sessions show a presence list of joined users, and each user opens their own custom views rather than one shared whole-warehouse view.
