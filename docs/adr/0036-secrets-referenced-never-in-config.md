# Secrets are referenced by name, never stored in Config

Config is versioned, hashed into every run fingerprint, and copied into replay inputs — so a credential pasted into Config would live forever in retained run artifacts and break replay of every past run when rotated. Therefore Config holds only secret references (names); the values live in a separate secret store (v1: an env/secrets file on the gateway and worker hosts) and are injected into adapters at runtime. Secret values never appear in Config versions, fingerprints, replay logs, checkpoints, or traces, and rotating a value never invalidates a replay because the fingerprint hashes the reference, not the value. Most current external services are plain and unauthenticated; this channel exists for the ones that are not, and for infrastructure credentials (Postgres, ClickHouse).
