# Boring auth: admin-created accounts, session cookies, per-project roles

Hellspawn is an internal tool, so v1 auth is deliberately boring: admins create accounts (no self-signup, no email verification, no reset flows), the gateway issues session cookies on email+password login, and every command, session join, and artifact read (playback recordings, replay logs, interaction logs) is checked against project membership. The gateway also keeps an audit log: logins, executor-seat changes, and every user command with the issuing account — so anything a real system received in a live run stays attributable to a person. Roles are per project — developer (author Worlds, Configs, Scenarios) and member (run scenarios, join sessions); the Executor/Viewer seat is a session concern, not an account role. One column of foresight: users.external_identity stays nullable so OIDC/Entra SSO can bolt onto the same user rows later without rework.
